What the app does

Reconstructs the investor's actual portfolio. The app processes Moomoo trade exports to rebuild open and closed positions, weighted-average cost, broker fees, realized P/L and unrealized P/L.

01 · Problem

Broker trade exports are not portfolio analytics.

A raw Moomoo trade history records individual executions, but it does not directly answer the questions an investor actually cares about: current cost basis, realised and unrealised profit, portfolio return, market exposure or risk-adjusted performance.

Project objective: turn raw brokerage transaction data into a reusable portfolio-analysis workflow that reconstructs positions, measures actual investor performance and adds market-risk analytics in one interactive dashboard.
02 · How it works

From trade-export CSV to portfolio analytics

The application separates transaction reconstruction, live valuation, actual investor performance and historical risk modelling.

STEP 01

Upload trades

Import a Moomoo trade-export CSV containing executed transactions, quantities, prices, currencies and fees.

STEP 02

Reconstruct positions

Process buys and sells chronologically to rebuild open and closed positions using weighted-average cost and realised P/L calculations.

STEP 03

Fetch market data

Retrieve current and historical security prices, FX rates, benchmark data and a U.S. Treasury-bill proxy through yfinance.

STEP 04

Generate analytics

Calculate actual money-weighted performance, current position metrics and backward-looking portfolio risk before displaying and exporting the results.

03 · Core analytics

Performance and risk are measured separately.

Actual investor performance

Calculates current market value, realised and unrealised P/L, estimated dividends, total P/L and money-weighted return using XIRR.

Position-level analysis

Reconstructs shares held, weighted-average cost, current price, remaining cost basis, portfolio weight, fees and position-level returns.

Historical risk analytics

Estimates annualised return, CAGR, volatility, beta, Sharpe ratio and Jensen's alpha using the current portfolio weights over the selected historical window.

Benchmark comparison

Compares the current-weight portfolio against a selectable market benchmark and visualises both total and systematic risk-return relationships.

04 · Technical design

A separate analytics engine keeps the calculations independent of the UI.

The project separates the Streamlit front end from the core portfolio analytics engine. The user interface handles file upload, settings and result presentation, while the engine performs trade reconstruction, valuation, performance calculations, risk estimation and reporting.

Python analytics engine

Pandas and NumPy handle transaction processing, portfolio calculations and tabular analytics.

Live market integration

yfinance supplies security prices, foreign-exchange data, benchmark histories and the risk-free-rate proxy.

Streamlit interface

Users can upload trade data, select the benchmark and historical window, review warnings and interact with the resulting analytics.

Automated reporting

The application generates an Excel workbook containing summary, allocation, position, trade, XIRR, methodology and warning sheets.

05 · Methodology choices

Distinguishing what the investor earned from what the portfolio historically implies

A central design decision was to keep actual investment performance separate from hypothetical historical portfolio analytics.

  • Weighted-average cost: remaining position cost basis is reconstructed chronologically, while partial sales realise P/L against the blended cost immediately before the sale.
  • Trade-date FX: non-USD trades and fees are converted using FX data around the original transaction date rather than today's exchange rate.
  • XIRR: actual dated buy and sell cash flows, estimated dividends and current portfolio value are used to estimate money-weighted annualised return.
  • Historical analytics: today's portfolio weights are applied retrospectively to historical returns for risk modelling and benchmark comparison.
  • Benchmark dependence: beta and Jensen's alpha depend on the benchmark selected by the user.
  • Risk-free proxy: the latest 13-week U.S. Treasury-bill yield is used for Sharpe-ratio and Jensen-alpha calculations.
06 · Limitations

What the dashboard should not be interpreted as

  • Historical current-weight returns are backward-looking estimates and are not the investor's realised historical return.
  • Risk estimates depend on the selected history window and may become noisy when holdings have limited overlapping price histories.
  • Market prices, FX data and dividend information rely on Yahoo Finance coverage and may differ from broker records or execution prices.
  • Estimated dividends may differ from actual cash receipts because of withholding tax, missing data or corporate actions.
  • Complete trade history is required for reliable cost-basis and XIRR reconstruction; unsupported or incomplete transaction histories can trigger methodology warnings.
  • Short positions are not supported by the current portfolio engine.
07 · Recruiter takeaway

What this project demonstrates

This project demonstrates the ability to translate a practical investment problem into an end-to-end analytics product: cleaning brokerage data, implementing portfolio-accounting logic, integrating live financial data, calculating performance and risk measures, designing an interactive interface and communicating methodological limitations clearly.
